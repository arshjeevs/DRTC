Setup v2's conditions (lab/PLAN.md, "Setup v2", locked 2026-11-22): **generated by `_make.py`, never edited by
hand**. Each file is one system under one fault, `<system>__<fault>.yaml`; `../v2_robot/` holds the same systems for
the real robot (the real network, no simulated latency).

| Systems | |
|---|---|
| `upstream_patient` | LeRobot's scheduler, starvation grace and request deadline = the whole trial (the baseline) |
| `upstream_shipped` | LeRobot's defaults (1 s grace, 5 s request deadline); bench only |
| `drtc` | DRTC (our version) with the same whole-trial limits |
| `a1_no_cooldown`, `a2_upstream_estimator`, `a3_upstream_trigger`, `a4_half_chunk_cap`, `a5_smin_half`, `a5_smin_x1_5` | DRTC with one part removed or changed (ablations) |
| `s_<method>` | DRTC + one smoothing method: `butterworth`, `adaptive`, `rtc`, `ensemble`, `zero_lag`, `ramp`, `butterworth_adaptive` |
| `stack`, `stack_minus_<part>`, `stack_nortc...` | the final stack and its ablations (written with `--stack` once it is chosen) |

Faults: `none`, `spike` (one reply +1 s), `drops` (replies lost for 1 s), `outage` (1.5 s, both directions), `mix`
(all three), `rise` (+400 ms for 5 s), `loss` (10% of replies). The bench files add the simulated network
(250 ± 20 ms) and the seeded 0-4 s fault shift per trial number.

```bash
.venv/bin/python lab/experiments/v2/_make.py                        # the conditions
.venv/bin/python lab/experiments/v2/_make.py --evals                # + the v2 eval files (not frozen ones)
.venv/bin/python lab/experiments/v2/_make.py --stack adaptive,rtc,zero_lag,ramp --evals   # + E3b and E4
```
