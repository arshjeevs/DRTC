# H200 GPU server

Training on the shared H200 server (`gpuh200`, 192.168.41.118), following the server guide *"Tensorflow & PyTorch in H200 GPU Server"*. The guide's rules come first; the lab tools work the same as elsewhere once inside the container.

## Rules (from the server guide)

- Connect with SSH; check `nvidia-smi` and pick a **free** GPU device from `nvidia-smi -L` (a MIG slice when MIG is enabled).
- Use the provided image `nvcr.io/nvidia/pytorch:26.02-py3` (pull it only if missing). No custom images.
- `docker run -it --rm --gpus device=<ID> -v /home/<user>:/workspace -p <port>:8888 <image>`.
- Work through Jupyter (`jupyter-notebook` inside the container), in the browser or through an SSH tunnel.

Our additions, all inside those rules:

| Addition | Why |
|---|---|
| `--shm-size=16g` on `docker run` | Data-loading worker processes share batches through `/dev/shm`; Docker's 64 MB default crashes them |
| `--name drtc_lab` | To find our container among the others |
| Everything in `/home/jayaraj/drtc_lab` | One folder; other users' folders and containers are never touched |
| `chown` back to the server account (`h200-setup`, `h200-own`) | The container runs as root (guide default); without it, files could only be deleted through docker |
| One training run at a time | The GPU is shared with other students |

The account is shared: anyone using it can read `drtc_lab`, including `.secrets.env`. Use tokens with the narrowest scope that works.

## First time

```bash
ssh jayaraj@192.168.41.118
git clone -b drtc https://github.com/arshjeevs/DRTC.git ~/drtc_lab       # once
# create ~/drtc_lab/.secrets.env with HF_TOKEN=... and WANDB_API_KEY=..., then: chmod 600 ~/drtc_lab/.secrets.env
tmux new -s drtc_lab                        # keeps the container alive after logout
~/drtc_lab/lab/bin/h200-start               # guide steps 2-5; prints the Jupyter address
# now inside the container:
cd /workspace/drtc_lab && lab/bin/h200-setup        # ~10 min, once
cd /workspace && jupyter-notebook                   # guide step 6; copy the token
# detach from tmux: Ctrl-b then d; log out
```

Open the printed address (`http://192.168.41.118:<port>`) or tunnel it (`ssh -L <port>:localhost:<port> jayaraj@192.168.41.118`, then `http://localhost:<port>`), paste the token, and open **New → Terminal**.

## Every time

In the Jupyter terminal:
```bash
cd /workspace/drtc_lab && git pull
lab/bin/train smolvla_cubebox_v1_lora      # same commands as on the other machines
lab/bin/logstats smolvla_cubebox_v1_lora
```
Closing the browser does not stop training. Watch it in wandb (project `drtc`).

## Stopping early, and continuing later

The server is shared, so a run may have to stop at any time. Stopping keeps everything:

| To stop | Do |
|---|---|
| In the run's terminal | **Ctrl-C once** |
| From any other terminal | `lab/bin/stop <model>` (or `lab/bin/stop --all`) |

The run finishes its current step (seconds), saves a checkpoint with the optimizer state, pushes it to
the Hub (model so far + training state) and prints how to continue. A second Ctrl-C quits at once
without saving (only the last periodic checkpoint is kept then).

```bash
lab/bin/train <model> --resume                 # continue to the planned end
lab/bin/train <model> --resume --epochs=100    # or to a new total (train longer when there is compute)
```
`--resume` works on any machine: without the local run folder it downloads the pushed checkpoint and
training state. Each log line shows progress, time left and finish time (`lab/bin/logstats <model>`).

## When the container stops

Exiting it, or a server reboot, removes the container (`--rm`); `drtc_lab` stays. A run killed this way keeps only its last periodic checkpoint (`save_freq`); stop it first when you can. Start again with `tmux new -s drtc_lab` + `~/drtc_lab/lab/bin/h200-start`, then `jupyter-notebook`. No setup needed. Interrupted training continues with `lab/bin/train <model> --resume`.

## Cleaning up

- Inside the container, `lab/bin/h200-own` gives new files (checkpoints, logs) back to the server account.
- Delete checkpoints you no longer need once a model is on the Hub: `rm -rf ~/drtc_lab/outputs/train/<model>`. `/home` is shared and ~88% full.
